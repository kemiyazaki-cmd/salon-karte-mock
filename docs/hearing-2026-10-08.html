設計書の一覧モック

ヒアリング質問リスト（2026-10-08 17:00 Zoom）

目的: 要求定義書・要件定義書の「（仮）」を潰し、Scope 1（初版で作る範囲）を確定する。 進め方: 事業計画書を一緒に見る（1） → 設計に効く7つの確認（2） → 現状の数字（3） → 資料の受け渡し（4）。 所要の目安: 60 分。1 に 20 分、2 に 25 分、3 と 4 に 15 分。

1. 事業計画書を見ながら確認すること

# 確認したいこと なぜ聞くか（設計のどこが決まるか） 今の仮置き
1-1 誰が払うか。サロンが直接払うか、スクールが払って生徒に提供するか テナントを誰が作るか、AI の利用上限を誰が決めるか、解約時にデータが誰のものか、が全部変わる。最優先 スクールがテナントを作ってサロンに渡し、スクールが上限を決める
1-2 料金の形。基本料だけか、基本料 + AI 従量か。月1万円以内はどこまで固いか 従量にするなら利用量の見える化と請求見込み表示が初版から必要。固定なら上限管理だけでよい 基本料 5 千〜7 千円 + AI 従量。合計の中央値 1 万円以内
1-3 対象顧客。スクールの生徒だけか、一般のサロンにも売るか。将来広げるなら時期 生徒限定なら「スクールが伴走する前提」で設定画面を薄くできる。一般向けなら自己登録と説明が要る 当面は生徒限定
1-4 業態の内訳。生徒サロンのうち、エステ・脱毛・眉毛・ネイル・まつエクの割合 初版で用意するカルテ項目テンプレートの優先順位。写真が核の業種が多いなら写真機能を厚くする エステ（フェイシャル・痩身・脱毛）中心
1-5 体験→本契約の2段階で営業している店の割合 来店種別「体験」と成約率の KPI を初版に入れる価値があるか 2段階が多数
1-6 差別化の訴求。計画書で何を売りにしているか 要求定義書の4点（月1万円以内・小規模特化・入力させない・伴走）と言葉を合わせる。違っていれば計画書側に寄せる 上の4点
1-7 提供の順序と時期。いつ・誰に・何から出す想定か Scope 1〜3 の切り方と、初版に入れる機能の線引き CRM → 紙・写真・音声メモ → フォーム・名寄せ → 提案・再来店・分析
1-8 スクール側の役割の具体。オンボーディングを誰が何時間やるか。コンサルで見たい数字は何か スクール横断ビューと個別閲覧の要件。見たい数字が KPI の定義になる 顧客数・記録件数・最初の1件までの日数・継続状況・入口の構成
1-9 収益見込みの前提数字。店舗数・単価・継続率 KPI の仮置き値を計画値に置き換える すべて（仮）

2. 設計に直接効く7つの確認

# 質問 選択肢の例 答えで何が変わるか 今の仮置き
2-1 録音と音声メモ、現場で受け入れられるのはどちら？ お客様との会話を録る形と、施術後にスタッフが30秒だけ独り言で吹き込む形。会話録音なら「画面を閉じても・他のアプリを開いても録り続ける」は必須か？ 会話録音が本命／音声メモで十分／両方。バックグラウンド録音が必須か 初版に入れる方。会話録音の実費は音声メモの10倍以上（90分×1日5人で月約9千円、無音を削って約3千円）。配布はストアの専用アプリを標準にする方針（確定）。確認は「生徒にアプリをインストールしてもらう導入は現実的か（Apple ID を持っているか・インストールの手伝いが要るか）」 アプリ版を標準。Apple 開発者登録は宮崎側で手配
2-2 契約書は特定商取引法の書面？ コース契約は1か月超かつ5万円超か。概要書面と契約書面を渡しているか。クーリングオフや中途解約の対応をしたことがあるか 該当する／しない／店による 該当するなら契約書は「法令対応の記録」として扱い、保管期間と有効期限・精算の情報を持つ。しないなら単なる預かり書類 該当する前提
2-3 スクールとして生徒の記録をどこまで見たい？ → 確定: 全部見られる前提。確認は「サロン側に閲覧の履歴が残る形で問題ないか」だけ — 閲覧履歴の表示の有無 全部閲覧可・履歴あり
2-4 生徒が実際に使っている集客・予約ツールは？ ホットペッパービューティー（サロンボード）、LINE 公式アカウント、minimo、Instagram、紙だけ、など 具体名と割合 連携の優先順位。LINE は API 連携できる。サロンボードは API が無いので CSV 取り込みになる LINE と予約サイトが多い
2-5 店の端末は共有タブレット？ 各自のスマホ？ 共有1台／各自スマホ／両方 共有なら来店記録ごとに施術者を選ぶ操作が必須。ログインの持ち方も変わる 両方ありうる
2-6 紙カルテに最低限必要な項目は？ 業種で違う？ スプレッドシートの列と照らし合わせたい 業種別に列挙 初版のカルテ項目テンプレートの中身 業種共通の最小セット + 写真
2-8 予約はどこで管理している？ 予約サイトの管理画面・Google カレンダー・紙の予約表・LINE のトーク。1日の予定を朝どうやって把握しているか 具体名と割合 ホームの「今日の流れ」に予約を自動で出せるか。Google カレンダーなら連携できる。予約サイトは通知メールの転送になる。紙なら朝に手で足す運用 手で足す（初版）、Google カレンダー・メール転送は Scope 3
2-7 禁忌の確認は毎回やっている？ 何を聞いている？ 妊娠・服薬・日焼け・生理・既往歴・金属アレルギーなど 業種別に列挙 当日チェック項目の既定リスト。安全上の警告の出し方 脱毛・光施術は毎回確認

3. 現状の数字（KPI の仮置きを実測値に置き換える）

分かる範囲で。感覚値でもよい。

# 聞くこと 置き換わる KPI
3-1 カルテ1件を書くのに今どれくらいかかっている？（紙・手打ち） 1来店あたりの作成時間「3分以内」
3-2 来店のうち、当日中にカルテを書けている割合 当日記録率「90%」
3-3 退店時に次回予約が入る割合 次回予約率「50%」
3-4 体験から本契約に進む割合 成約率「40%」
3-5 新規客がもう一度来る割合。メニューごとの来店周期（フェイシャル・脱毛・痩身） 周期内再来率「+10 ポイント」、メニュー既定の周期
3-6 1店舗の顧客数の目安（紙カルテの枚数）。予約サイトに入っている顧客数 移行率「80%」、検索の規模感
3-7 1日の施術人数、1回の施術時間 音声の量 → AI 実費の見込み
3-8 客単価の目安、物販の比率 客単価「+5%」

4. 受け取る資料

# 資料 用途 状態
4-1 AI カルテの事業計画書 位置づけ・料金・対象・提供順序の正 当日 Zoom で共有
4-2 以前スプレッドシートで運用していた「理想のカルテ」 カルテ項目・運用手順の正。なぜ続いた／やめたかも聞く 共有待ち
4-3 実際の紙カルテ 数枚（個人情報はマスクまたは見せてもらうだけ） 紙取り込みの受入テスト用。手書きの読み取り精度の目安 要依頼
4-4 使っている同意書・契約書・問診票のひな形 書類の種類と抽出項目の確定 要依頼
4-5 予約サイトから出した顧客一覧（CSV。1〜2行のサンプルでよい） 持ち込み機能の列対応 要依頼

5. 聞かれそうなことへの答え（準備）

  • いつ使える？ → 設計を今週で固め、初版はカルテの土台（顧客・来店記録・写真・紙取り込み・音声メモ・同意）から。具体的な時期は設計確定後に出す
  • 月いくら？ → 基本料 + AI 使った分、合計で月1万円以内に収める設計。AI は使った分だけ見える
  • 録音は怖がられない？ → 会話を録らなくても、施術後の30秒の独り言で同じ結果になる。両方できるようにする
  • 紙はやめないといけない？ → やめなくていい。撮れば取り込まれる。紙で続けるスタッフがいても成立する
  • データは誰のもの？ → サロンのもの。スクールは許可した範囲だけ見る。辞めるときは全部持ち出せる

回答は 01-request.md の未確定事項（1〜12）と 02-requirement.md のスコープに反映する。
