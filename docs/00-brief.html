salon-karte ── 構想メモ（要求定義 /design-request の入力）

作成: 2026-10-07。知り合い（サロン経営 ＋ サロン経営スクール事業）からのヒアリングを宮崎が整理。

誰の、何の問題か

  • 対象: 個人〜小規模サロン（美容・エステ等）の経営者とスタッフ
  • 問題: カルテの「入力・管理・分析」の工数が重く、業務の大半がそこに割かれる
    • 結果: 施術時間が取れない／忙しすぎる
    • もしくは そもそもカルテを作っていない（記録ゼロ）
  • 出所: スクール事業で多数の生徒（サロン経営者）をコンサルして見えた共通ボトルネック
  • 制約: 利用者の IT リテラシーは低い。スマホしか触れない人がいる前提で設計する

作りたいものの全体像（知り合いの構想・全部入り）

土台は サロン向け CRM（ToB でいう HubSpot / Salesforce の「顧客管理」をサロン用・低リテラシー向けに作り直したもの）。 その上に以下を載せる。

# 機能 内容
0 顧客管理（CRM基盤） 顧客台帳・来店履歴・施術履歴。全機能の土台
1 録音→カルテ自動入力 施術中の会話をスマホで録音 → 文字起こし → カルテ項目へ自動入力 → 本人が確認・保存
2 次回提案の自動生成 溜まったカルテから「次回この顧客に何を気をつけるか」を自動で出す
3 再予約 Push の自動化 顧客ごとに「いつ再予約を促すか」を判定して自動で通知
4 全体分析 全顧客・全カルテを横断して「どうサービス改善すれば売上が上がるか」を自動分析
5 紙・PDF との併用（2026-10-07 追加） 紙カルテをスマホで撮影→自動でその顧客の記録に。契約書等の PDF を預けると重要項目が構造化されて自動入力され、元の PDF も顧客から引き出せる。紙を捨てさせない前提
6 スクール向けの横断ビュー（2026-10-07 追加） 生徒サロンごとの定着状況・入口／既存ツールの利用状況を横断で見る。許諾のもと記録を一緒に見てコンサルする基盤

設計フェーズで決めること（宮崎メモ）

  • 要件は全体（0〜4）で定義し、実装の順番だけ段階に分ける
    • 前回実測: 画面14枚・テーブル12個で Claude の利用枠が尽き、レビュー1回飛ばし → 重大4件含む18件が後出し
    • 候補順: 0（CRM） → 1（録音カルテ） → 2 → 3 → 4。2〜4 はカルテが溜まらないと成立しない
  • スマホ前提の画面設計（片手操作・大きいボタン・入力は極力させない）
  • 録音の同意（顧客の会話を録る）と個人情報の扱い。カルテは要配慮情報を含みうる
  • 文字起こし／生成 AI の実費。上限設定が必要
  • 「カルテを作っていない人」が最初の1件を作れるまでの導線が最重要

確定した方針（2026-10-07・設計フェーズ着手時）

  • 対象業種はエステ・脱毛・眉毛・ネイル・まつエク等。美容室（美容師）は想定しない（スクールの生徒にほぼいないため。2026-10-07 確認）

  • 月1万円以内（基本料 + AI 従量の中央値。仮）。中小エステの支払い上限（友人ヒアリング）。AI 実費は従量で見える化

  • 権限の既定は「店の全員が全顧客を見られる」。担当限定はオプション（2026-10-07 確認）

  • 会話録音の同意記録は持たない（当事者録音。2026-10-08 確定）

  • スマホ向けはストア配布の専用アプリを標準にする（App Store / Google Play。同じ Next.js の画面を Capacitor 等のネイティブの殻で包む。殻が録音のバックグラウンド継続・カメラ・通知を担う。Web はスクールの PC 利用と予備経路。2026-10-08 確定）。Apple 開発者登録・初回審査・Mac でのビルドが運用に乗る。基盤づくり（Foundation）の段階で殻を先に作り、Apple 開発者登録と初回審査を初版の実装と並行して進め、TestFlight で生徒サロンに配る（2026-10-08 合意）

  • 会話録音はアプリ版で「閉じても録り続ける」。Web で使う場合だけ録音アプリから取り込み

  • 差別化は4点: 月1万円以内／個人〜小規模特化／入力させない／スクールの伴走と横断コンサル。「保存する」ではなく「使う」カルテ（要求定義書 §0）

  • スマホ主、タブレット・PC も対応（1つのレスポンシブ Web アプリ。2026-10-07 確認）

  • UI のトンマナは高級サロン・スパの文法（アイボリー基調・金のヘアライン・明朝の見出し・深いブロンズの塗りボタン・角丸ほぼ無し）。初版のテラコッタ案は「ちゃっちい」で破棄（2026-10-07）。全画面に3段までの階層行（パンくず）を常設

  • ログインはメール＋パスワード（端末記憶 30 日・メールで再設定。2026-10-08 確認）

  • UI は「瞬間起点」で設計（施術前の30秒・施術後の1分・閉店後の5分）。ホームは「次のお客様」ヒーロー＋今日の記録リング、顧客詳細は「この人カード」＋タブ、来店記録は3ステップ、スマホは下部タブ（2026-10-08・第3版。まず4画面に適用）

  • ホームの「今日の流れ」は予約表ではない。次回予約日・今日の記録・朝に手で足した人だけが並ぶと画面に明記。外部予定（Google カレンダー／予約通知メール転送）の取り込みは Scope 3（FUNC-31）。名寄せは「片方を残す」ではなく「記録は全部残し、属性は項目ごとに選ぶ」（2026-10-08 指摘で修正）

  • スクールは生徒サロンの記録を全部見られる（許諾設定は作らない。閲覧履歴のみ残す。2026-10-08 確定）

  • 顧客・来店データの CSV ダウンロードは初版から（FUNC-30 (a)）。原本込みの一式持ち出しは Scope 2

  • 専用 SaaS として作る。サロン1店舗＝1テナント。スクール事業が提供者で、オンボーディング伴走 + データを見てコンサルする役割を持つ（要求定義書 §0）

  • ベースは Sprint1（Next.js + Supabase + Vercel）のまま進める。Sprint3（ローカル実行・Agent SDK・FastAPI）には乗り換えない

    • 理由: 利用者がスマホから使う公開サービスなのでローカル実行前提と合わない。LLM 利用は「構造化出力の一発呼び出し」が主で、エージェント主役の構成ではない。既存の失敗46件ルールが Next.js / Vercel / Supabase 向け

  • Sprint3 から借りるもの: agent-plan.md の作法（完了条件を判定方法とセットで書き、評価の合格基準にする）。03-spec の後に /r2b:design-agent を1回走らせ、LLM 処理（録音→カルテ・PDF/紙取り込み・次回提案・全体分析）の完了条件と評価シナリオを書く

  • インフラは Supabase（東京リージョン）+ Vercel（hnd1）。AWS は、要配慮情報の保管場所について契約・規約で専用環境を求められた場合のみ再検討（その場合は /r2b:design-infra で 07 を足す）

  • 要件定義の非機能要件に必ず入れるもの: LLM と音声認識（文字起こしは LLM と別サービス）それぞれの実費上限／録音・書類の同意と保管期間／東京リージョン固定

  • 全体分析（機能4）だけはエージェント的になりうるが、実装順が最後なのでその時点で判断する

実装前に潰す技術的な不確実点（2026-10-08 整理）

全31機能は技術的に実装可能。確度に差があるのは次の5つで、上の2つは 基盤フェーズの最初に試作・実測して確認する。

# 不確実点 確認方法 外れたときの逃げ道
1 アプリ版（Capacitor）のバックグラウンド録音を iOS で継続できるか（既製部品で足りるか、自前のネイティブ処理が要るか） 録音だけの試作を実機に入れ、画面消灯・他アプリ使用で5分録れるか確認 Web と同じく端末の録音アプリから取り込み（FUNC-14 の補助経路）を初版の標準にする
2 手書きの紙カルテの読み取り精度 友人から実物を数枚もらい、設計確定前に実測。記載項目のうち正しく入った割合を数える 読めない箇所は空欄で返し「元画像を見て直す」運用（仕様どおり）。精度が低すぎれば初版は画像保存のみに下げる
3 施術室の BGM・小声での文字起こし精度 友人のサロンで音声メモを数本録って実測 候補を直す運用で吸収。無音・BGM 除去を入れる
4 書類（契約書・同意書）の項目抽出の当たり外れ ひな形をもらって試す 既存値と並べて選ぶ設計なので外れても壊れない（Scope 2）
5 予約通知メールの書式変動・Google カレンダー連携の審査期間 主要1〜2社のメール実物で確認 Scope 3 のまま。手で「今日来る人を足す」が標準

実装で必ず出る構成上の注意: 音声・画像・PDF は端末から Supabase Storage に直接上げ、文字起こし・抽出・生成は Vercel の関数の外（Supabase Edge Functions か、ジョブ実行サービス）で非同期に回す。Vercel の関数は実行時間と受け取れるサイズに上限があり、60分の録音ファイルはその中で処理できない。要件の「非同期・確認待ちに届く」はこの構成を前提にしている。基盤フェーズで AD として確定する。

量の見込み: Scope 1 は画面14枚・テーブル15前後で、前回（14枚・12個）とほぼ同じ規模。初版は「顧客・来店記録・写真・音声メモ・同意・CSV」を先に通し、「紙カルテ読み取り・書類預かり・スクール集計」を後半に回す順で、利用枠が尽きても使える状態で止まれるようにする。
